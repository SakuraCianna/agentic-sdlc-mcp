# v1.10.0 发布说明

> 发布日期：2026-08-13。发布目标为 `v1.10.0`；不可变 Git commit、npm 完整性值、MCP Registry 记录和 GitHub Actions 结果以正式发布后的远端记录为准。

## 版本重点

v1.10.0 把项目从“handler 测试通过”提升到“协议、客户端、场景、预算和故障边界都有独立证据”。运行时迁移到稳定 MCP TypeScript SDK 2.0.0 分包，继续支持 2025 legacy 客户端，并为本地 stdio/loopback HTTP 显式验证 `2026-07-28` era。公开契约仍为 13 个工具和 5 个资源，没有增加远程 OAuth、多租户、共享 session store 或公网监听。

## 协议与契约

- 生产依赖精确固定 `@modelcontextprotocol/server`、`node`、`express` 2.0.0，开发期 client 同为 2.0.0。
- stdio 使用官方 `serveStdio`；loopback HTTP 使用官方 modern handler，并保留受限 2025 legacy profile。
- 同一 factory/handler 服务 2025 和 2026 era，13 tools / 5 resources discovery、schema、annotations、Markdown/structuredContent 和默认 dry-run 语义保持一致。
- v1.9.0 的不可变 discovery manifest 固定到 tag/commit；当前比较只发现预期的 server version 1.9→1.10，以及官方根 schema 从 draft-07 到 JSON Schema 2020-12 的兼容 dialect 变化，0 个未解释 breaking change。
- Inspector 2.0.0 分别从进程外验证 stdio 与 loopback HTTP；Conformance 0.1.16 作为固定 legacy pilot，记录 5 个 direct pass 和 25 个有治理信息的 expected gap。它们是兼容证据，不是 MCP 官方认证。

## Agent evaluation 与发布门禁

- provider-neutral scenario/trace schema、固定 scorer、digest golden 和跨字段可满足性验证已进入仓库。
- 6 个 `recorded-agent` selection trace 来自脱敏历史使用记录，并用固定 GitHub fixture 和真实 MCP 2.0.0 client 重放。
- 6 个 `scripted` critical scenario 覆盖安全 triage、release/evidence/handoff 组合、提示词注入、写权限、repo/ref 固定和 fail-closed gate。
- 13 个公开工具都有 GitHub calls、recursive items、Markdown characters、structured JSON bytes、duration、timeout/cancellation 与固定 P95 预算。
- 11-case GitHub fault matrix 覆盖 401/403/404/422/429/500、GraphQL partial、timeout/cancellation、301 截断、主字段缺失与重复响应。
- `Contract and evaluation (Node 24)` 已成为 `main` required check。它要求 12 个场景总正确率至少 90%、critical 组 6/6、budget 13/13、fault 11/11，并只上传 manifest diff、Conformance checks、scenario score、budget 与 fault 五个脱敏 artifact。

required CI 当前是 6 个 recorded replay 加 6 个 scripted scenario，`live-model` 为 0。这里的 12/12 与 critical 100% 只证明固定离线题目和录制工作流保持确定性；不能推导为当前模型、所有供应商、未来提示词或任意真实仓库上的选择准确率。

## 安全与可靠性

- 提示词注入矩阵覆盖 Issue/PR/comment、README/CONTRIBUTING/规则、workflow/job/log 与 GitHub error text；已采集边界通过真实 MCP/policy/error path，未采集边界以零 ingestion 证明。
- evidence Markdown 与 structured gate 对 omitted/incomplete source fail closed；注入不能扩大 repo/ref、关闭 dry-run、触发 live create、读取环境凭据或进入发布 artifact。
- PR supplemental secret scanner 对 JSON/JSONC、多行 credential、容器、escaped keys、known formats、深层/超大输入和多语言 ternary/postfix syntax 建立有界回归；package-lock、UI accessKey 与响应 token metadata 误报已收紧，真实凭据仍 fail high。
- GitHub 错误不再回显不可信上游正文或普通内部异常；固定可信本地配置诊断、timeout 和 cancellation 类别仍保持可行动。
- 分页基于原始响应页长，页内重复不会截断后续页；300/301 边界保持不完整证据 fail closed。
- 所有 CI checkout/setup/upload Actions 固定到完整 commit SHA；发布和 Registry OIDC 流程继续验证 tag、main ancestry、package/lock/server/registry 版本一致性。

## 使用本 MCP 参与开发得到的结论

真实自托管审查能准确聚合 required checks、mergeability、Gitleaks provenance、CODEOWNERS 和证据缺口，并能在 PR 正文补齐 threat/permissions/secrets/rollback 后给出可解释变化。v1.10 开发也暴露并修复了多类假阳性：安全文档 URL 的 work type、`Part of` 追溯语义、中文安全章节、原子范围理由、token budget metadata 和 Verification 命令证据。

当前仍有两个使用边界：

1. 长驻本地 MCP 进程不会热加载新构建或刚合并的代码；升级包或切换构建后必须重启 MCP 连接再复验。
2. reviewer 是保守启发式门禁，不是人类判断替代品；明确证据缺失应补齐，确认的假阳性应通过成对回归修复，而不是降低门槛或忽略整个业务上下文。

## Node.js 与本地运行

- 正式运行范围仍为 Node.js 22+；GitHub Actions 验证 Node 22 和 24。
- 维护者本机不需要同时安装两个版本，本机结果不能替代 CI 的另一运行时证据。
- Node 20 已结束维护，不提供兼容与安全承诺。
- stdio 仍是默认推荐传输；HTTP 只绑定 `127.0.0.1` loopback，不应暴露到局域网、互联网或反向代理后。
- 远程 OAuth/多租户仍是条件触发的未来重立项，而不是本版本能力。重新考虑时必须先完成独立身份、租户隔离、Host/Origin、请求级凭据、缓存/session/AbortSignal 隔离和并发威胁模型。

## 升级步骤

1. 安装 Node.js 22 或 24。
2. 将 MCP 客户端版本更新为 `agentic-sdlc-mcp@1.10.0`，或重新运行 `npx -y agentic-sdlc-mcp@1.10.0`。
3. 保持现有最小权限 `GITHUB_TOKEN`、`GITHUB_OWNER`、`GITHUB_REPO` 与 `SDLC_DEFAULT_BRANCH` 配置。
4. 完全重启 MCP 客户端连接，避免长驻进程继续使用旧 `dist`。
5. 先调用 `repo_context` 和只读 gate 验证连接；写操作继续使用默认 `dryRun:true` 预览。
6. 消费 structuredContent 的客户端应容忍 additive 字段，并按 trust boundary 把仓库文本视为不可信数据。

## 已知限制与风险

- Prompt-injection 与 secret heuristic 是可解释的有界防线，不是自然语言或全程序安全证明；语义改写、同形字、跨文件数据流等仍需把来源当成不可信证据。
- recorded-agent replay 不证明当前模型实时能力；required CI 不使用模型凭据。
- 2025 stateless HTTP 无法把单独 cancellation POST 可靠关联到既有请求；需要服务端取消时优先使用 stdio 或 2026 profile。
- 发布候选已在允许范围内把 Hono 更新到 4.13.1，并把开发链的 brace-expansion/nanoid 更新到已修复 patch；完整与 production `npm audit` 当前均为 0。项目仍只通过 `getRequestListener` 使用 Node adapter，没有静态文件服务，也未导入 Hono CORS、JSX memo、proxy 或 language middleware。audit 0 不是未来版本的可达性证明；若加入这些 middleware、静态文件路由或升级 SDK lock，必须重新评估。
- Conformance pilot 的 expected gaps 是本产品公开契约与 upstream everything-server fixture 的差异，不得为清零数字添加测试专用生产能力。

## 回滚

如果 v1.10.0 出现兼容问题：

1. MCP 客户端临时固定到 `agentic-sdlc-mcp@1.9.0` 并重启连接。
2. 若 npm `latest` 需要回退，维护者把 dist-tag 指回 1.9.0，并对 1.10.0 添加明确 deprecation 说明；已发布版本不可覆盖或复用。
3. GitHub Release 保留失败记录；修复使用新 patch 版本，不重发同一 1.10.0。
4. 保留 immutable v1.9.0 contract baseline、critical 100%、budget/fault 完整性和 required checks；不得通过删除门禁掩盖故障。
5. 若问题仅在 Inspector/Conformance/evaluation 设施，使用普通 revert PR 回退对应切片；不要替换产品 transport 或扩大权限。
6. 记录 Node 版本、transport/protocol era、tool、脱敏输入形状、structured/Markdown channel、GitHub 权限状态和失败 workflow URL。
